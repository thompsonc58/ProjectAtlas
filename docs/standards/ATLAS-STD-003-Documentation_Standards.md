# Atlas Documentation Standards

> **Establishing clarity, consistency, and maintainability across every
> document in Project Atlas.**

------------------------------------------------------------------------

# Purpose

The Atlas Documentation Standards establish the conventions for
creating, organizing, and maintaining written artifacts throughout
Project Atlas.

Well-engineered documentation improves collaboration, reduces ambiguity,
supports long-term maintenance, and ensures a consistent experience for
every contributor and reader.

Documentation is a deliverable---not an afterthought.

------------------------------------------------------------------------

# Documentation Principles

Every document should be:

-   Clear
-   Accurate
-   Concise
-   Complete
-   Consistent
-   Maintainable
-   Accessible
-   Professional

When writing documentation, prioritize understanding over complexity.

------------------------------------------------------------------------

# Standard Document Structure

Unless a specific artifact requires otherwise, major Atlas documents
should follow this structure:

1.  Title
2.  Purpose
3.  Scope
4.  Definitions (if applicable)
5.  Main Content
6.  Examples or References
7.  Governance or Responsibilities (if applicable)
8.  Closing Statement

A predictable structure improves readability and navigation.

------------------------------------------------------------------------

# Writing Standards

Documentation should:

-   Use active voice whenever practical.
-   Write in complete, professional sentences.
-   Define technical terms before using them.
-   Eliminate unnecessary repetition.
-   Avoid ambiguous language.
-   Use inclusive, student-centered terminology.
-   Favor precision over verbosity.

The goal is communication---not decoration.

------------------------------------------------------------------------

# Headings

Use a logical heading hierarchy.

``` text
# Document Title

## Primary Section

### Subsection

#### Supporting Detail
```

Headings should clearly describe the content that follows.

------------------------------------------------------------------------

# Lists

Use bullet lists for collections.

Use numbered lists for ordered procedures.

Keep list formatting consistent throughout each document.

------------------------------------------------------------------------

# Tables

Use tables whenever structured information improves readability.

Examples include:

-   Metadata definitions
-   Version history
-   Responsibilities
-   Standards
-   Comparison matrices

------------------------------------------------------------------------

# Code Blocks

All examples should use fenced code blocks.

Specify a language whenever appropriate.

``` text
Example
```

Code examples should demonstrate best practices.

------------------------------------------------------------------------

# Images and Diagrams

Visual elements should:

-   Support the written content
-   Include descriptive captions
-   Be referenced within the document
-   Remain readable when viewed independently

Diagrams should simplify understanding rather than add complexity.

------------------------------------------------------------------------

# References

Whenever possible, reference related Atlas artifacts using relative
repository links.

Examples:

-   Engineering Principles
-   Repository Standards
-   Atlas Information Model

Documentation should encourage discovery across the repository.

------------------------------------------------------------------------

# Tone and Style

Atlas documentation should be:

-   Professional
-   Encouraging
-   Objective
-   Engineering-focused

Avoid unnecessary jargon, slang, or informal language.

Every document should reflect the professionalism expected of an
engineering organization.

------------------------------------------------------------------------

# Revision Practices

Documentation should be reviewed whenever:

-   Standards change
-   Curriculum changes
-   Technology changes
-   Industry expectations evolve
-   Errors are discovered

Continuous improvement applies to documentation just as it applies to
curriculum.

------------------------------------------------------------------------

# Quality Checklist

Before publication, verify that the document:

-   Has a clear purpose
-   Follows Atlas formatting standards
-   Contains complete information
-   Is grammatically correct
-   Uses consistent terminology
-   Includes required metadata
-   References related artifacts where appropriate
-   Has completed the required review process

Documentation should be release-ready before entering the repository.

------------------------------------------------------------------------

# Closing Statement

Professional documentation strengthens collaboration, preserves
institutional knowledge, and ensures that Atlas remains understandable
and maintainable for future contributors.

Clear documentation reduces uncertainty.

Consistency improves quality.

Well-engineered communication creates better learning.
