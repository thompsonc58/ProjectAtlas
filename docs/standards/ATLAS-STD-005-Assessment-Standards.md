# ATLAS-STD-005

# Assessment Standards

## Purpose

The Atlas Assessment Standards establish the engineering principles,
requirements, and quality criteria for designing, implementing,
evaluating, and continuously improving assessments throughout the
Project Atlas framework.

Assessments are engineered artifacts designed to produce measurable
evidence of student learning, competency attainment, and curriculum
effectiveness.

These standards promote consistency, traceability, authenticity, and
continuous improvement across all Atlas-engineered curricula.

## Scope

This standard applies to every assessment artifact developed within
Project Atlas, including but not limited to:

-   Diagnostic Assessments
-   Formative Assessments
-   Summative Assessments
-   Performance Assessments
-   Laboratory Exercises
-   Capstone Projects
-   Practical Demonstrations
-   Presentations
-   Written Reports
-   Quizzes and Examinations
-   Reflective Activities

## Guiding Principles

All Atlas assessments shall adhere to the following principles:

### Validity

Assessments shall measure the competencies and learning outcomes they
are intended to evaluate.

### Reliability

Assessment results shall be consistent regardless of instructor or
delivery method.

### Authenticity

Whenever appropriate, assessments shall mirror professional practice and
industry expectations.

### Fairness

Assessment design shall minimize unnecessary barriers and bias.

### Transparency

Students shall understand assessment expectations, evaluation criteria,
and grading methods before beginning the assessment.

### Accessibility

Assessments shall comply with institutional accessibility requirements
and Universal Design for Learning (UDL) principles where applicable.

### Alignment

Every assessment shall directly support defined learning outcomes and
competencies.

### Continuous Improvement

Assessments shall be reviewed and improved using data collected from
implementation.

## Assessment Philosophy

Within Atlas, an assessment is not simply an assignment.

An assessment is an engineered mechanism for collecting evidence that
demonstrates competency attainment.

> **What evidence demonstrates that the learner has achieved the
> intended competency?**

Completion alone shall not constitute evidence of learning.

## Assessment Types

  Assessment Type   Primary Purpose
  ----------------- -------------------------------------------------
  Diagnostic        Measure prior knowledge
  Formative         Guide learning during instruction
  Summative         Evaluate learning after instruction
  Performance       Demonstrate authentic competency
  Reflective        Promote self-assessment and professional growth

## Assessment Alignment

Every assessment shall map directly to:

-   Program Outcomes
-   Course Outcomes
-   Module Outcomes
-   Learning Objectives
-   Competencies

Assessments lacking documented alignment shall not be approved for
release.

## Assessment Engineering Lifecycle

1.  Requirements Analysis
2.  Assessment Design
3.  Development
4.  Validation
5.  Implementation
6.  Evaluation
7.  Continuous Improvement

Assessments shall be version controlled in accordance with
**ATLAS-STD-004 -- Versioning Strategy**.

## Assessment Requirements

Every Atlas assessment shall include:

-   Assessment title
-   Purpose
-   Assessment type
-   Competencies measured
-   Learning outcomes measured
-   Instructions
-   Required resources
-   Deliverables
-   Evaluation criteria
-   Associated rubric
-   Success criteria
-   Estimated completion time
-   Academic integrity requirements
-   AI usage policy (when applicable)

## Authentic Assessment

Whenever feasible, assessments should require students to perform work
representative of professional practice, including:

-   Software development projects
-   Database design
-   Code reviews
-   API development
-   Technical documentation
-   System design
-   Team presentations
-   Live demonstrations
-   Portfolio artifacts

## Evidence Standards

Every assessment shall identify the evidence that demonstrates
competency.

Evidence may include:

-   Source code
-   Technical documentation
-   UML diagrams
-   Database schemas
-   Presentations
-   Demonstrations
-   Git repositories
-   Reflection papers
-   Peer evaluations
-   Videos
-   Design artifacts

Grades shall be based on evidence rather than completion.

## Assessment Metadata

Suggested metadata includes:

-   Atlas ID
-   Version
-   Assessment Type
-   Difficulty Level
-   Estimated Time
-   Module
-   Learning Outcomes
-   Competencies
-   Rubric Reference
-   Version History

## Quality Assurance

Before release, every assessment shall verify:

-   Competency alignment
-   Learning outcome alignment
-   Appropriate cognitive complexity
-   Clear instructions
-   Appropriate difficulty
-   Accessibility compliance
-   Industry relevance
-   Rubric availability
-   Observable evidence of learning

## Continuous Improvement

Following each implementation, assessment effectiveness should be
evaluated using:

-   Student performance trends
-   Rubric effectiveness
-   Difficulty calibration
-   Student feedback
-   Instructor observations
-   Industry relevance
-   Technological changes
-   AI impact

Assessment revisions shall follow the Atlas Versioning Strategy.

## Compliance

All Atlas curriculum artifacts containing assessments shall comply with
this standard.
