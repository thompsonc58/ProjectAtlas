# ATLAS-GDE-001

# Question Engineering Guide

## Purpose

The Atlas Question Engineering Guide provides recommended practices for
designing questions that produce valid, reliable, and meaningful
evidence of learning.

Questions are engineered to evaluate competency---not memorization.
Every question should intentionally measure a defined learning
objective.

------------------------------------------------------------------------

## Engineering Philosophy

Within Atlas, a question is an evidence collection instrument.

Its purpose is not simply to determine whether a student knows an
answer.

Its purpose is to reveal what a student understands, how they reason,
and whether they can apply knowledge to authentic situations.

Every question should answer:

> **What evidence of competency will this response provide?**

------------------------------------------------------------------------

## Question Design Principles

Every Atlas question should be:

-   Clear
-   Purposeful
-   Unambiguous
-   Competency-Aligned
-   Authentic
-   Accessible
-   Appropriate for the learner's level
-   Free of unnecessary complexity

Questions should measure knowledge---not reading comprehension unless
reading comprehension is the intended competency.

------------------------------------------------------------------------

## Competency Alignment

Every question should map directly to:

-   Learning Objective
-   Module Outcome
-   Course Outcome
-   Program Competency

Questions without documented alignment should not be included in
assessments.

------------------------------------------------------------------------

## Bloom's Taxonomy

Atlas recommends intentionally designing questions across multiple
cognitive levels.

  Level        Evidence Expected
  ------------ ----------------------------
  Remember     Recall information
  Understand   Explain concepts
  Apply        Solve problems
  Analyze      Compare or diagnose
  Evaluate     Justify decisions
  Create       Produce original solutions

Balanced assessments should evaluate more than factual recall.

------------------------------------------------------------------------

## Question Types

Atlas supports many question formats, including:

-   Multiple Choice
-   Multiple Response
-   True / False
-   Short Answer
-   Essay
-   Programming Exercise
-   Database Design
-   Case Study
-   Debugging Exercise
-   Code Review
-   UML Design
-   Oral Defense
-   Presentation
-   Reflection
-   Peer Evaluation

The format should support the competency---not the other way around.

------------------------------------------------------------------------

## Engineering Multiple-Choice Questions

Well-designed multiple-choice questions should:

-   Test one concept
-   Include one clearly best answer
-   Use plausible distractors
-   Avoid "all of the above"
-   Avoid "none of the above" when possible
-   Avoid grammatical clues
-   Avoid trick wording
-   Avoid unnecessary negatives

Multiple-choice questions should assess thinking, not guessing.

------------------------------------------------------------------------

## Engineering Authentic Questions

Whenever appropriate, questions should simulate professional practice.

Instead of:

> What command creates a table?

Prefer:

> Design a database schema that satisfies the client's requirements and
> justify your design choices.

Instead of:

> What HTTP status code indicates success?

Prefer:

> Your API returns a 500 error after deployment. Identify the likely
> cause and describe your troubleshooting process.

Authentic questions measure applied knowledge.

------------------------------------------------------------------------

## AI-Aware Question Design

Atlas recognizes that AI tools are part of modern professional practice.

Question design should consider:

-   Appropriate AI use
-   Restricted AI use
-   Required disclosure
-   Reflection on AI-assisted work
-   Evaluation of student reasoning
-   Original decision-making

Questions should assess human understanding, even when AI tools are
permitted.

------------------------------------------------------------------------

## Common Anti-Patterns

Avoid questions that:

-   Reward memorization alone
-   Depend on trivia
-   Contain hidden clues
-   Measure multiple concepts simultaneously
-   Use subjective wording
-   Penalize reading ability unnecessarily
-   Lack alignment
-   Have multiple defensible answers without explanation

------------------------------------------------------------------------

## Quality Checklist

Before approval, ask:

-   What competency does this question measure?
-   Is the wording clear?
-   Is the difficulty appropriate?
-   Could another instructor interpret it consistently?
-   Does it produce observable evidence?
-   Is the expected answer defensible?
-   Does it align with learning outcomes?
-   Does it remain relevant as technology evolves?

## Continuous Improvement

Questions should be reviewed using:

-   Student performance statistics
-   Item difficulty
-   Item discrimination
-   Instructor feedback
-   Student feedback
-   Technology changes
-   Industry relevance

Questions should evolve through version control.

------------------------------------------------------------------------

## Closing Philosophy

Questions are not merely prompts.

They are engineered mechanisms for collecting evidence of learning.

A well-engineered question reveals competency.

A poorly engineered question measures chance.

Atlas seeks to engineer questions that accurately, fairly, and
consistently reveal what learners know, understand, and can do.
